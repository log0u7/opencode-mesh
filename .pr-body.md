## Summary

Six fixes found by the real mesh_spawn e2e (leader `opencode run` in a temp repo, worker in a native worktree):

1. `serve`: ephemeral-port fallback when the mesh port is taken (worker sessions load the same plugin as the leader).
2. `worktree`: reuse the plugin's in-process fetch for run mode; second pass extracts it from the v1 client's HeyApi core (`_client.getConfig().fetch`) instead of the global fetch (which cannot reach `opencode.internal`).
3. `sqlite`: resolve the `bun:sqlite` module (OpenCode's compiled runtime exposes neither `globalThis.Bun.sqlite` nor `node:sqlite` to hot-loaded plugins) with a node:sqlite fallback for tests.
4. `spawn`: workers default to `--agent build` so they execute instead of entering plan mode.

E2E result after fixes: mesh_spawn -> native worktree -> headless worker wrote hello.txt (exit 0) -> mesh_workers completed -> mesh_worker_logs captured output -> mesh_worker_remove(force) cleaned worktree + row.
